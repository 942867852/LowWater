## 1. 系统概览与目标（对应支柱/动词）

### 1.1 定位

概念文档把"自主日程 NPC"定为本作的信息载体（P2）；S2 让每个人有一条能被背下来的轨迹。**本份是这条轨迹唯一被玩家看见的方式**——如果 S9 没做对，S2 的一切模拟等于不存在。

- **支柱**：**P2（主，本份是它的唯一兑现者）**——"读不懂的模拟等于没有模拟"；**P1**——信息载体必须是**世界里的一件东西**（板上的字、门上新加的锁），不是 HUD 上的抽象图标；**P3**——阅读不暂停世界，缺位是信息；**P4**——HUD 不给回报、不给数字让你算。
- **动词**：**读 OBSERVE** 的全部呈现件落在本份（本作主打美学 Discovery 的载体）；其余 7 动词的**输入入口与反馈出口**亦在此。**本份不产生动词，只让动词可执行。**
- **反目标**：不做全图任务面板 · 不做 NPC 追踪器/头顶信息板 · 不做上帝视角地图 · 不做感官奇观 · 不做"帮助玩家理解"的提示弹窗。

### 1.2 一句话职责

> 让玩家**用眼睛读世界**就能知道"谁、几点、在哪、缺什么"——并且让他清楚地知道：**他手上的界面，是世界的一部分，不是世界的替代品。**

### 1.3 三条自建红线（比裁决更严的自我约束）

| # | 红线 | 理由 |
|---|---|---|
| **U-A** | **正式 HUD 不含任何"关于世界的答案"**：不告诉你在哪、不告诉你找谁、不告诉你他几点来。HUD 只承载**玩家自身状态 + 时间**。 | 一旦 HUD 给出答案，Core 验收 2 立刻失真（测试者会读 HUD 而非读世界），P2 被自己击穿。 |
| **U-B** | **任何信息在任一画质档下都必须有非色相、非听觉、非时限的载体。** | 承接 `accessibility.md` §1.2 Basic 准入底线；本作信息通道全部落在渲染预算内，无"性能不够就砍通道"的借口。 |
| **U-C** | **所有信息视觉复用同一套形状字母表**（`accessibility.md` §2.1），S9 **不自建第二个图标集**。 | 与"防第二套骰子"同款纪律；玩家只需学一张表。 |

## 2. 核心概念与数据模型

### 2.1 信息四层（HUD 越少越好，答案全在第 3、4 层）

| 层 | 载体 | 常驻？ | 内容 |
|---|---|---|---|
| **L-0 世界内物件** | 板、笔记、价格牌、门锁、脚印、灯 | 是（在世界上） | **一切答案**：谁几点在哪、缺什么、世界变没变 |
| **L-1 情境层** | 需求气泡、携带物剪影、交互提示、字幕 | 否（进 `observeRadius`/视野才出现） | **关于具体的人的即时信息** |
| **L-2 常驻层** | 时钟 + 昼夜色温 · 生理四值 · 负重 · 欠条页入口 | 是 | **只有玩家自身状态与时间**（U-A） |
| **L-3 开发层** | 调度甘特、压力热力、归因链、RNG、LOD、性能 | **否，永不进正式构建** | 一切数字与真相（`DebugSnapshot`） |

> **设计公理**：**答案的层越深，玩家越有"主动发现"的感觉。** L-0 是 Discovery 的舞台，L-2 是生存压力表，L-3 是给我们的，不是给玩家的。

### 2.2 数据模型

```text
HUDPresenter      { level: "MINIMAL"|"STANDARD"|"VERBOSE", physioMode:"SEGMENT"|"NUMBER", ... }
BubbleView        { actorId, slots:{ physio:Glyph, safety:Glyph, social:Glyph, creed?:Glyph },
                    severityMotion:0|1|2|3, motionEnabled:bool }
SubtitleCue       { cueId, layer:"SPEECH"|"OVERHEAR", speakerRef?|nullRing, textKey, tokens, ttlMin, persists }
OverhearCue       { topicSeedId, fidelity:"FULL"|"PARTIAL"|"MUFFLED", textKey, listenersSeen }
LongTextSession   { docId, sourceRef, pages[], readCursor, bookmark, openedTick, isDialogue:intentId? }
BoardReadState    { inObserveRadius:bool, boardId?, note:{frozen:WorkOrder[], frozenAt} | null,
                    lastRefreshTick }
InteractPrompt    { targetRef, kind ∈ {TAKE,READ,TALK,USE,TEND,ALIGN}, legibleInRadius:bool }
TimeScaleState    { choice:"STANDARD"|"SLOW", effectiveTimeScale, saveMarked:bool }
```

### 2.3 全局形状字母表（**引用，不重建**）

**唯一编码源 = `accessibility.md` §2.1**，本份逐字复用，禁止新增：

- **形状 glyph（10 值闭集）**：水滴 · 碗 · 月牙 · 竖菱形 · 双扣环 · 盾 · 火焰 · 排夹 · 十字 · 芽。
- **底盘（3 值）**：**圆形** = 需求/状态｜**方形** = 物资/簇｜**无底盘** = 一个人（只有名字 + 职业形状）。
- **fill（3 档，非可数）**：空心描边 / 半填充 / 实心+粗描边。
- **消歧规则（必须实现）**：竖菱形在**圆底盘**读作"怕/安全"、在**方底盘**读作 `AMMO`；其余 9 glyph 单义。

> **S9 的用法**：需求气泡槽位、字幕说话者名签、工作板介质标记、地图手绘记号、容器标记、`observeRadius` 内交互提示——**六处同一套表**。任何"这里想再画个图标"的诉求，必须先证明它落在 10 glyph × 3 底盘内，否则不予立项。

### 2.4 相机与交互距离（第三人称近视角的功能约束）

| 项 | 规格 | 依据 |
|---|---|---|
| 相机 | 第三人称近视角；眼高 ≈ **1.6m**（R-S1 垂直元素的屏幕投影依据） | `accessibility.md` §4 R-S1 |
| `observeRadius` | `4 + 0.6 × MIND` **m**（地板 **4.0m** @ MIND=1） | S0 §D |

## 3. 规则与公式（可读性预算、信息层级、可见性判定、字幕时序）

> 本节全部规则**只投影、不判定**；所有求值满足 `control-manifest.md` B4（表现层无判定）。

### 3.1 信息层级规则

**A. 三层显示上限（防认知过载）**

```text
同时气泡 ≤ BUBBLE_MAX_CONCURRENT(3) / NPC        // accessibility A-4
同时字幕 ≤ 2 行                                   // accessibility §6.1
同时偷听碎句 ≤ 1 条（新袭旧，旧条入日志）           // §3.3-C
工作板条目 ≤ 3 / 社区（含沉降后）                  // S5 GAP_SIGNAL_MAX / S7 §3.6
欠条页 ≤ 3 条                                     // S4 §6-3
社区面板读数 = 3 个（信条 / 产能 / 缺口）           // S5 §6-1
```

**B. 信息优先级（拥挤时谁退让）**——`世界信号 > 沉浸字幕 > 需求气泡 > 常驻 HUD`。
理由：世界信号承载"世界变了"，是 P3 的唯一提醒；常驻 HUD 只是数字，随时可查，最该让位。

**C. urgency 的非数字表达（裁决 21 的机械落点）**

| urgency | 语言标签 | 载体介质（**非可数**） | 板面状态 | 附加物 |
|---|---|---|---|---|
| 1 | 「还行」 | 折角纸片塞板缝 | 完整 | 无 |
| 2 | 「明天紧」 | 炭笔，边缘被雨晕开 | 完整 | 无 |
| 3 | 「今天就要」 | 刀刻进木头，木屑未落 | 刻痕处划破 | 无 |
| 4 | 「有人在挨」 | 赭红颜料**压住旧字** | 反复擦出毛面 | 板边挂**空杯** |
| 5 | 「已经在死」 | 钉上木牌，字是烙/凿 | 板面**被刨掉一层** | 牌上挂**实物** |

- **单射性**：介质 ∈ {纸片,炭,刻,赭红覆盖,加钉木牌} 已是 5 个互异值 → 与 1–5 单射；板面状态与附加物提供两级冗余。
- **u4/u5 红标降级为冗余**（裁决 32 / `accessibility` §5.2）：真正的判据是"板面被改造了"与"板边挂了东西"；关掉色相后仍可区分。
- **禁止**：`★` / `▮▮▮` / 刻度 / 进度条 / 任何"有几个单位"的表达。数字 1–5 只进 `DebugSnapshot`。

**D. 排序可接受，序数不可接受（裁决 33）**

- **允许**：板条目按 S7 §3.2 的 `sortKey` 呈现（`urgency desc` → `staleness desc` → `haulFit asc` → `travelMinQuantized asc` → `clusterScarcityRU desc` → `communityId asc` → `orderId asc`）——**顺序是世界事实**，不因玩家改变。
- **禁止**：行号、`1.` `2.` `3.`、缩进分级、列表点、`>>` 标记、"优先级 N"。条目之间以**空行 + 介质差**分隔，不以序号分隔。
- 校验：`--assert-board-no-ordinal`（静态检查条目模板中序号类字段数 = 0）。

### 3.2 可见性判定

**A. 需求气泡显示条件**

```text
显示 ⇔ ( isNamed(actor) 或 dist(player, actor) < 30m )
      且 屏幕尺寸 ≥ BUBBLE_MIN_SCREEN_H(1.6% 屏高 ≈ 17px @1080p)
槽位   : 12 点=生理(水/食/睡取最急者) · 10 点=安全 · 2 点=社交 · 6 点=信条(默认关)
运动   : severity 1 静止 / 2 呼吸缩放(0.90–1.05, 2.4s) / 3 急跳+摆角 15°(0.8s)
静态替身: 运动关闭时，severity 由形状边缘破损承载（完整/缺口/斜线划裂）
```

**B. 工作板读取（裁决 5 / S7 §B-6）**

```text
inObserveRadius = dist(player, Board.locationId) ≤ observeRadius
可读 ⇔ inObserveRadius                                  // 不做 Tab 全图面板，无例外
离开 → 生成 BoardNote{ frozen: WorkOrder[], frozenAt:{dayKey, minuteOfDay} }
       笔记页顶部**必须**显示 frozenAt，且行程时间与 state **会过期**（P3 在 UI 层的唯一兑现）
进入任一板前 → 重新刷新（frozenAt 更新）
boardId : he_valley.board_01 / jing_cell.board_01（S8 §2.2）
```

**C. 社区仪表 / 欠条页 / 队列**

```text
社区仪表 = 3 读数（信条 3 条 · 产能 staffingRatio + 空岗 · 缺口 ≤3 条）
         SCARCE(编制<0.60) 与 TIGHT(safeDays≤5) **两个指示量，禁止合并为一个灯**（C-18）
pending 条目（站队/声望/价格）一律标「明日生效」（S0 §B5 下游只读昨日快照）
欠条页   = ≤3 条 × 6 字段（谁/什么/多少/哪天/还差多少/冻结在哪）；deadlineDay−1 转红
```

**D. 距离分档与信息三不变（承接 ADR-003：视锥已移出 simLOD）**

| 距离带 | 载体 | 可判读内容 |
|---|---|---|
| 0–8 m | 需求气泡 + 姿态 + 携带物 | 完整：他在做什么 + 他缺什么 |
| 8–25 m | 携带物剪影 + 步频 + 剪影轮廓 | activity 粗分类（取水/守夜/巡线/修补/育儿/闲坐/睡/警觉） |
| 25–60 m | 剪影轮廓 + 是否自带光源 | 静止 / 移动 / 有灯（三值） |
| > 60 m | 一个点 | 只承诺"那里有人" |

- **N1 不变内容**：任一 `renderLOD` 档位下，「activity 粗分类 + 需求气泡状态」都有至少一个可见载体。
- **N2 不变时刻**：载体切换只发生在可读性保持锥（±25°/±20°）**之外**，0.2s 交叉淡入，**禁 pop**。
- **N3 不变语义**：编码表全局唯一，不因距离/画质/昼夜改变含义；升级只增加冗余，不替换语义。
- **细信号钳制（裁决 35）**：线状信息载体（绊线）**屏幕空间最小宽度 ≥ 1.5px**（`LINE_MIN_PX`），关闭该层抖动；**不依赖抗锯齿方案**。

### 3.3 字幕时序（含 gossip 偷听）

**A. 台词字幕（对话层）**

```text
出现 : 与音频起音同步（±1 帧缓冲）；无音频时随动画起势
停留 : ttlMin = clamp(2.0 + 0.35 × len(字符), 2.0, 8.0) 游戏秒 ≈ 实时秒（TIME_SCALE=60）
       —— 即"阅读无时限"由**可延长**承担，不由"世界暂停"承担
上限 : 同时 ≤ 2 行；超行即分页（同一 cue 内翻页，不新开 cue）
名签 : glyph（取该 NPC 的 homePost 形状）+ 名字 + 固定侧位；**颜色不作唯一判据**（三重：glyph/字重/侧位）
底 板: 对比比 ≥ 4.5:1（背景暗化 + 文字亮化），**不用纯黑遮罩**；α 默认 0.70，可调
```

**B. 偷听碎句（`layer = OVERHEAR`）——D4 的关键信息通道**

```text
触发 : NPC 的 SOCIAL 块交谈输出**结论句**时（S2 §6-6 规定"恰好漏出一句"）
保真 : 由距离×遮挡的**几何**决定（确定性键，零随机）
       6–10m 且无遮挡 → FULL（全句）
       10–16m 或有遮挡 → PARTIAL（缺 1–2 词，用 `……` 占位）
       >16m            → MUFFLED（仅"墙那边有两个人在说话"，可能漏出一个名字）
呈现 : **不进字幕主队列**，进独立的"耳边的字"层 —— 斜体 + **无名签**（空环：只有底盘、无 glyph = "你不知道是谁"）
       M注意：无底盘=人 的规则在此**退化为空环**，这是 §2.3 底盘规则的复用，零新增概念
时序 : 起音同步；ttlMin 与 FULL 同级（PARTIAL 不因缺词缩短——保证可读时间不缩水）；新袭旧，旧条立刻入日志
```

**C. 与"名声先你一步到达"（D4）的协同**

- 偷听是玩家**唯一**能提前听见"别人嘴里的我"的渠道——因为没有任何 NPC 会当面替你复述传言。**字幕层就是 D4 的听觉形态。**
- **缺词（`……`）本身是叙事装置**：信息不全 → 传闻不可靠 → 玩家产生"我得去搞清楚/去澄清"的自设目标（呼应 D4 的"澄清误会"整类目标）。
- **失真可听**：`--dump-gossip` 的"原话 → 你听到的话"在**正式构建中降级**为：玩家若先后在两地听到同一 `topicSeedId` 的两句不同话（如"他帮我们取过水" → "他替人卖命"），日志页把两条**并列**显示——允许玩家自己发现"话在变"。**不标注"失真"二字**（不给答案）。
- **与 S4 CALLBACK 的分工**：CALLBACK 是**当面的**回声（谈完 D+1 生效）；偷听是**背后的**回声（当场可听）。二者共同构成 P1"任何因果 ≤3 跳落到具体的人"的可感知面。
- **禁止**：为"让玩家听懂"而在偷听层加注解、箭头、方向指示、人物高亮。**玩家不知道是谁说的，这本身就是设计。**

**C. 与世界照跑协调（P3 不妥协 —— 裁决 34）**

1. **打开长文本面板不暂停世界**。面板是 UI 覆盖层；玩家在其打开期间仍可被世界影响（被偷、被围观、饿渴照常衰减）。
2. **唯一允许"收起面板"的情形 = S0 §B3.4 的三条中断规则**（`THREAT_NEARBY` / `CRITICAL_NEED` / `COMMUNITY_ALARM`）。这不是 S9 新增的暂停，是底座既定的强制中断；中断后播一句收束文本 + 保留书签。
3. **对话型长文本**（程九 3 段自白）受 S4 §4.1 会话状态机约束：离开 `DIALOGUE_OPEN_RADIUS` → `ABORTED`，`pendingEffects` 丢弃，未闭合段落**不算说过**。**静态长文本**（终端/遗书）无此约束，可随时离场再回。
4. **面板可缩为角落小卡**（阅读偏好），小卡状态不遮挡画面中心 → 玩家可边读边看世界。
5. **禁止**：阅读时黑屏、全屏暗化演出、打字机音效逐字吐字（默认关，可选项）、配音口型特写——全部属 Sensation 或认知负担。

> **本份的回答**：这条**不可能**靠 S9 单方面实现，但 S9 必须提供下列**七个信息通道**，其中 C-1–C-4 是**必要条件**（缺一即该验收结构上不可达）。

| # | 通道 | 它回答的问题 | 不看 UI 时的可读性判据 |
|---|---|---|---|
| **C-1** | **时间锚**：昼夜色温四档（晨/午/昏/夜）+ 三个世界标点（06:00 出工灯灭·聚集·散开 / 正午影子最短 / 黄昏宵禁前分粮） | "现在几点" | 关掉 HUD 时钟后，仅凭色温 + 世界标点可区分晨/午/昏三档；三名受试对三档的时刻估计误差 **≤1 游戏小时**；三档与 `{TIME_PHRASE}` 逐字对齐 |
| **C-2** | **岗位可辨**：无底盘 = 人 + 岗位 glyph 名签（8 岗位各一形状） | "他是干什么的" | 同一 NPC 的形状在两日内**逐次观察完全一致**（N3 语义不变）；受试能用形状说出 8 岗位中的 ≥6 个 |
| **C-3** | **路线可读**：近乎固定的通勤路线 + 被踩实的旧径 + 岔口脚印链 | "他这时候在哪条路上/在不在路上" | 同一 NPC 两日**路线重合**；偏离**只**在有 C-7 信号时发生（R-A `homePost` 世袭 + 零随机抖动，S2 §1.3） |

| **C-6** | **需求钟位**：气泡四钟位（12 生理 / 10 安全 / 2 社交 / 6 信条默认关） | "他现在缺什么"（辅助，非位置通道） | 同一需求状态两日内钟位不变；运动可关且有静态替身（边缘破损） |
| **C-7** | **变化预告**：四类 WorldSignal（脚印偏离 / 加灯加人 / 柜子搬走 / 绊线），**信号先于行为 ≥6 游戏小时** | "他的作息变了没有"（预测失效时的补偿） | 信号 `installTick` ≤ 行为生效 tick 前 ≥6 游戏小时（S2 §4.1）；**信号只能让玩家修正预测，不能事后才告诉他** |

**关键设计点（写给主理人）**：验收 2 的盲测条件是"**不给任何 UI 文字提示**"。因此——
1. **HUD 时钟的文字不算"提示"**（它是时间读数，不是关于 NPC 的答案），但**为了不依赖它**，C-1 额外提供色温 + 世界标点两套非文字载体。三名目标时刻 **06:00 / 12:00 / 20:00 恰好落在晨/午/昏三个不同档位**，色温曲线本身即可消歧。**盲测必须同时跑"关闭时钟"对照组**（裁决 B-1 已接受"时钟不计入提示"，但为校准 C-1 权重，须在关闭 HUD 时钟的条件下重跑同一协议）：若关闭时钟组命中率 **< 70%**，则 **C-1（昼夜色温 + 三个世界标点）的权重需上调**，并加强其非文字时间载体，直到关钟组回到 ≥70%（见 §8 验收 A1、A13）。
2. **C-2 + C-3 + C-4 是"人 → 岗位 → 路线 → 地点"的推导链**：形状给出岗位，岗位来自 `homePost`（世袭、不变），路线近乎固定 → 位置可被预测。**这三个通道必须全部落在渲染预算内且不可被任何画质档关闭（§3.5-C）。**
3. **S9 不做"帮助玩家理解"的事**：不提示、不注解、不给箭头。**理解必须来自玩家自己的归纳**——这是 Discovery 美学的兑现，也是验收 2 能测到东西的前提。

### 6.4 交互与输入表现（要点）

- **判定前置面板**（S0 §A6）：档位名 + 数字（「苛刻 14」）+ 成功率 + `modTotal` 明细（可展开）；**置灰时明写缺什么**（"需 言辞 3" / "你带着他们的水"）。大成功/大失败 = 短促相机位移 + 音效 + **世界内具体后果**；**禁**慢镜头/命中停顿（Sensation + 与 P3 冲突）。
- **对话与欠条**：三类选项一眼可辨（普通 / `[言辞] …` 灰 + 档位 / `[你上次替我们守过夜] …`）；**不解释 effect，只回传 `optionId`**。欠条页 ≤3 条 × 6 字段；到期前一日转红 + 三选项（补交/以工抵债/求宽限）；**即时**反映账本事实（补偿 S4 的 D+2 延迟）。
- **负重与拾取**：负重面板呈现 kg / `speedMul` / 体力三轮，**无格子数**；拾取日志由 `needReason` 翻译为世界侧短句（"河口的取水口滤芯没了"），**无 "+N"**。

### 6.5 需求气泡与作息可视化（P2 的最终兑现）

- **默认只画三条**（生理/安全/社交）；信条槽默认关（裁决 36），仅 `ALIGN` 完成后或"高信息模式"开启。
- **两日可读定律的 S9 责任**：在同一 NPC 身上，C-2（形状）+ C-3（路线）+ C-4（剪影）+ C-5（台词）**四项在两日内全部可重复观察**，且**零随机抖动**（S2 §3.2 `startMin` 纯算术）。**S9 不新增任何随机化表现**（不随机晃动、不随机台词、不随机步频）。
- **06:00 是世界标点**：灯灭 → 门口聚集 → 人群定向散开，三步**时间上顺序固定**，方向各不相同。

### 6.6 工作板 · 笔记 · 社区仪表

- **板**（`he_valley.board_01` / `jing_cell.board_01`）：板头 1 个数字（`safeDays`）+ 趋势方向；条目 ≤3；介质承载 urgency；**无行号/序号/列表点**；**无"接受"控件**。
- **笔记**：离开 `observeRadius` 冻结，顶部**必须**显示 `frozenAt`（「记于 D3 06:12」）；行程时间与 state **会过期**（P3 在 UI 层的唯一兑现）。
- **TEND 条目**：写「那个位置今晚空着」，**不写"去顶岗"**；给时段档（「天黑到天亮」），不给坐标。
- **条目转 `RESOLVED` 时不解释**：`resolvedBy` 不进正式 UI。
- **空板**：显示「今天他们自己够了」+ `safeDays` 与 `trendDelta7d`（支撑 Core 验收 3 的自设目标）。

## 7. 边界情况与失败模式

**E1 · 玩家看不懂发生了什么（必须含 · 本份的头号失败态）**
- **判定**：Core 验收 2 命中率 <70%，或受试访谈中出现"我不知道他为什么在这儿/我不知道这算不算变了"。
- **诊断树（写进开发工具，不是给玩家的）**：用 `control-manifest.md` §2 埋点区分三种成因——① **作息不可读**（C-2/C-3 通道失效：形状不一致 / 路线抖动）→ 修 S2 侧（本份只报告）；② **信号没被看到**（C-7 的 `installTick` 与玩家经过 tick 差 > 0 且玩家从未进入 `observeRadius`）→ 修 S9 侧（可见性/尺寸/低照度）；③ **时间读错了**（C-1 色温档被误判）→ 修 S9 侧（色温曲线 ΔL\*）。
- **设计兜底**：**绝不**用"加一个提示"来兜底（那会击穿 U-A）。兜底 = **加强已有通道的冗余**（多一个非色相载体），边界是 §3.5-C 的 7 项不可关闭清单。

**E2 · 信号存在但玩家没进 `observeRadius`（信号被漏读）**
- 行为：信号**不追踪、不提示、不重复**——漏了就是漏了（P3：缺位是信息）。补偿：信号**不是一次性的**，只要状态未降级它一直在世界上（灯没被搬走、脚印没被踩平），下次路过仍可读到。

**E3 · 玩家转头后发现"他换了个活儿"（renderLOD 信息错乱，约束 2）**
- 判定：同一 NPC 的 activity 语义在载体切换前后不一致。规则：由 N1/N2/N3 保证（§3.2-D）——载体只改画法**不改语义**，切换只在可读性保持锥外。校验：`--assert-lod-invariance`。

**E4 · 阅读长文本时世界发生了不可逆的事**
- 行为：面板**不自动弹出**任何"你错过了什么"；合上后世界已是新状态。补偿：保留 bookmark 可续读；对话型长文本可能被 S4 会话 `ABORTED`（未闭合段落丢弃），静态长文本无影响。唯一例外：S0 §B3.4 三条中断规则（`THREAT_NEARBY`/`CRITICAL_NEED`/`COMMUNITY_ALARM`）→ 收起面板 + 播世界内事件。

**E5 · 字幕层与偷听层同时刷屏**
- 规则：**偷听层永不抢占字幕主队列**；同时偷听 ≤1 条（新袭旧），旧条立刻入日志；字幕 ≤2 行。两层的名签视觉可区分（字幕=有 glyph 名签；偷听=空环名签 + 斜体），故玩家仍能分辨"对我说的"与"我偷听到的"。

**E6 · 板笔记过期但玩家以为还是当前状态**
- 行为：笔记顶部**常驻** `frozenAt`；行程时间与 `state` 显示为**过去时**（「记于 D3 06:12 · 那时往东北 12 分钟」）。反制：进入**任一**板前即整体刷新；**不提供**"自动刷新"（那会让笔记变成追踪器）。

**E7 · 无障碍减速开启导致的存档/重放争议**
- 行为：`SLOW` 只改 `effectiveTimeScale`（每现实秒的 SIM_TICK 数），**不改任何 tick 内容**；`accessibilitySlow = true` 的存档，`worldHash`/`safeDays` 曲线/重放**逐位不变**（验收 6 不受影响），读档界面明示「非标准时间流速」。校验：`--assert-slow-determinism`。

**E8 · 低帧率下的信息通道降级**
- 降级顺序 = **后处理 → 环境细节 → 植被密度 → 阴影精度 → 贴图 mip**；**§3.5-C 的 7 项通道一律最后降且不关闭**。帧率 <30fps 时若某不可关闭通道被降级 → 报警（`--assert-critical-channels`）。

**E9 · 绊线在 TAA 下被吃掉（裁决 35）**
- 信号层做**屏幕空间最小宽度钳制 ≥1.5px** + 关闭该层抖动；默认 FXAA、默认关 TAA。校验：`--assert-line-minpx`。

## 8. 验收标准与调试钩子

**验收**

1. **A1 · Core 验收 2（本份主验收）**：按 `control-manifest.md` §2 盲测协议（release 构建、关闭一切调试 UI、无甘特面板）——受试自由游玩 2 游戏日后预测 3 名指定 NPC 在 06:00/12:00/20:00 的位置，**三选三命中率 ≥70%**。**且**七条通道（§6.1 C-1–C-7）在 Basic 档下**全部可用**。**且关闭 HUD 时钟的对照组**须同协议重跑（见 A13）。
2. **A2 · 信息通道的三重底线（U-B）**：随机抽取核心画面，在**关闭色相**、**静音**、**关闭运动**三种条件下，C-1–C-7 每条通道仍可判读；`--assert-legibility` 截帧校验 ΔL\* ≥ 18 与 4.5:1。
3. **A3 · 渲染预算**：1060 / 1080p 下信息通道合计 **< 1.20ms**（§3.5-A）；仿真成本 = 0；`src/render` `src/ui` 内 `rollCheck|makeSeedCtx` 命中 = 0（`control-manifest` B4）。
